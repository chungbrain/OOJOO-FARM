# Build 2026112011 개선사항

## 목표

Phase 6(FCM 푸시, 결제 게이트웨이, 모델 개인화)를 **코드 완결(code-complete) + 설정 게이트(config-gated)** 방식으로 마무리한 릴리스입니다.
실제 Firebase/Toss 계정 없이도 빌드·동작이 정상이며, 설정 값을 채우는 순간 해당 기능이 활성화됩니다.
또한 실기기에서만 검증 가능하던 **W5 관수 안전 로직**을 PC 시뮬레이션으로 이식해 테스트로 증명했습니다.

## 주요 변경

### FCM push (설정 게이트)
- **백엔드** (`src/lib/push.js`): FCM v1 HTTP API. 서비스 계정 키로 RS256 JWT 서명(node:crypto — 새 의존성 0개),
  OAuth 토큰 캐시(만료 5분 전 갱신), data-only 메시지 전송(라벨/색은 마스터 앱이 결정).
  - 활성화: env `FCM_PROJECT_ID` + `FCM_SERVICE_ACCOUNT`(키 JSON 경로 또는 인라인 JSON)
  - 미설정 동안은 완전 no-op(네트워크 호출 0건)
- **백엔드 이벤트 훅**: `dispatchMasterAlert()` — 기존 SSE chokepoint(단건+배치)에서 병행 호출.
  대상 = SSE 타입(`health_change`/`water_low`/`pest_detected`/`harvest_ready`) + `water_failed`/`battery_low`
  (SSE 비연결 시에도 도달해야 하는 하드웨어/배터리 알림). 수신 = 소유자 + 가구원 전체의 등록 디바이스.
- **백엔드 토큰 관리**: `POST/DELETE /api/users/:id/push-token`(20..256자, 중복 제거, 최대 10개), `users.push_tokens` 컬럼.
- **마스터 앱**: `FirebaseCfg.kt`(값 비어 있음 = 비활성) + `OojooApp`(Application)에서 **google-services 플러그인 없이**
  수동 Firebase 초기화. `FcmService`가 data 메시지를 기존 `notiLabel`/`notiColor` 매핑으로 로컬 알림으로 렌더링
  (인앱 알림과 동일 외관). 토큰은 로그인 전 보관(pending) 후 `bootstrap()` 에서 등록.
  Android 13+ `POST_NOTIFICATIONS` 1회 요청. 활성화: `FirebaseCfg` 에 google-services.json 값 채우기.

### Toss Payments (설정 게이트)
- **백엔드** (`src/lib/pg.js` + `src/routes/payments.js`): `PG_MODE` 스위치 — 미설정/`demo`(기본)는 기존 즉시 `paid`
  체크아웃과 **바이트 단위 동일** 동작. `PG_MODE=toss` 시:
  - 체크아웃 → `pending_payment`(재고 미차감)
  - `POST /api/payments/toss/start` — 서버가 secret 키로 결제 생성(`POST /v1/payments/requests`) → `approvalUrl` 발급
    (**클라이언트에는 Toss 키/SDK 없음** — Toss Android SDK가 가용 리포지토리에 없어 서버 주도 플로우 채택)
  - 브라우저에서 결제 승인 → 세 갈래 닫힘 루프(동시에 와도 멱등):
    - `POST /api/payments/toss/confirm` — 서버사이드 확인(`POST /gateway/payments/{paymentKey}`, 금액 검증)
    - `POST /api/payments/toss/webhook` — Toss 웹훅(로우 바이트 HMAC `tss_v1:hmac_sha256(secret, Toss-Timestamp + rawBody)` 검증,
      `express.raw` 로 `express.json()` 전에 마운트)
    - `POST /api/payments/toss/status` — 클라이언트 폴링용 서버 조회(`GET /gateway/payments/{key}`)
  - `paid` 마킹은 `markOrderPaid()` 단일 chokepoint — 트랜잭션 + `UPDATE ... WHERE status='pending_payment'` 가드로
    confirm·웹훅 경쟁 포함 **재고 차감은 딱 1회**. 취소는 `canceled`(재고 무영향).
  - 활성화: env `PG_MODE=toss` + `TOSS_SECRET_KEY` (+ 포털 웹훅 등록 시 `TOSS_WEBHOOK_SECRET`)
- **마스터 앱**: 체크아웃 응답 `status` 분기 — `pending_payment`면 approvalUrl 브라우저 열기 + 3초 간격 상태 폴링(최대 2분).
  결제 확정 시에만 장바구니 비움(취소/초기화는 재시도 가능). i18n 3문구(ko/en).

### W5 관수 안전 — 이제 테스트로 증명
- `simulation/src/engine/wateringSafety.js`: `FarmerEngine.kt` W5 로직의 **정확한 미러** 순수 상태머신
  (상승 엣지 히스테리시스, 30분 쿨다운(시도 시점 갱신·실패 포함), 성공 시에만 엣지 소모, 모든 소스 기준점 갱신,
  `water_failed`(hardware_offline/control_error), `battery_low` 20% 하락 엣지 + 1시간 쿨다운).
  시계/액추에이터/이벤트 sink 전부 주입 가능.
- `FarmerSim`의 `water` 명령이 이 상태머신을 경유(실기기 `doWater` 와 동일 경로).
- 테스트 9개 추가(시뮬레이션 게이트 15 → **24/24**): 지속 needWater 20틱/10시간 → 관수 1회, 쿨다운 차단,
  수동 관수 기준점 갱신, BLE 미연결 → 실패 보고 + 엣지 미소모 + 재연결 성공, 제어 오류, 배터리 단일 알림,
  관수량 클램프(50..2000ml), FarmerSim 통합 2건.

### 모델 개인화 원커맨드
- `ml/plant_health/personalize.sh --species X`: 백엔드 DB → 사람 확인 진단 프레임 export → 온디바이스 모델
  파인튜닝(합성 리플레이 포함) → round-trip 검증. **확정 프레임이 없으면 거절(exit 2)**.
  (양쪽 경로 실검증: 빈 DB → 거절+트린 클린, 시드 DB → export 45건/finetune val 0.5→1.0/모델 갱신 후 복원)
- `export_diagnosis.py` 경고 출력을 stdout → stderr(JSON stdout 기계 파싱 유지).

# Build 2026081002 개선사항

## 목표

Master와 Farmer 앱에서 서버(Master 백엔드) 주소를 앱 안에서 명시적으로 바꾸고, 연결을 검증한 뒤 다시 연결할 수 있는 설정 UI를 추가했습니다.

## 주요 변경

- Master 설정 화면과 Farmer 설정 화면에 "서버 연결" 섹션을 추가했습니다.
- 입력한 서버 주소를 `http/https + 호스트 + 선택 포트 + 루트 경로` 형태로 정규화하고, 사용자정보(user:pass)·하위 경로·쿼리·프래그먼트·잘못된 포트를 거부하는 검증기 `ServerEndpoint` 를 두 앱에 추가했습니다.
- "저장하고 다시 연결" 을 누르면 백엔드 `GET /health` 를 먼저 호출하여 정상 응답(`ok=true`)일 때만 주소를 저장하고 네트워크 클라이언트를 재생성합니다.
- 연결에 실패하면 기존 주소(및 Farmer의 페어링)를 그대로 유지하고 실패 메시지를 표시합니다.
- Farmer는 재연결에 성공하면 Foreground 서비스에 `RECONNECT` 액션을 보내 엔진을 재시작하고 세션키·주소를 갱신합니다.
- `ApiClient.baseUrl` 을 `@Volatile` 로 만들고, 검증 실패 시 `false` 를 반환하도록 `setBaseUrl` 을 강화했습니다. 비동기 `verifyBaseUrl` 로 `/health` 확인을 수행합니다.
- 서버 연결 관련 문자열을 한국어/영어 리소스로 추가했습니다.
- 두 APK의 버전 코드를 `2026081002`, 버전 이름을 `1.0.2026081002` 로 갱신했습니다.

## 검증

- `node scripts/verify-locales.mjs`
- `:master:app:testDebugUnitTest` (`ServerEndpointTest` 포함)
- `:slave:app:testDebugUnitTest` (`ServerEndpointTest` 포함)
- `:master:app:assembleDebug`
- `:slave:app:assembleDebug`
- 잘못된 주소(빈 값, 스킴 없음, `ftp`, 자격증명 포함, 하위 경로, 쿼리, 프래그먼트, 범위를 벗어난 포트)가 모두 거부되는지 단위 테스트로 확인했습니다.
- 정상 주소는 대소문자·여백을 정규화하여 루트 URL 로 저장되는지 확인했습니다.
- `/health` 성공 시에만 주소가 저장되고 재연결되는 흐름을 확인했습니다.

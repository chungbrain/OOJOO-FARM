# Build 2026112013 개선사항

## 목표

두 가지 신규 요구사항 완결:

1. **Farmer 사진첩 → 폰 갤러리** — 앨범 사진을 폰 갤러리의 `Pictures/oojoo`
   폴더에 발행해 갤러리 앱에서 열람 가능하게.
2. **Farmer 카메라 실시간 스트리밍** — 기존 3초 영상 캡처를 유지하면서,
   마스터가 Farmer 카메라를 실시간(MJPEG)으로 볼 수 있도록.

검증 과정의 부수적 발견(TCG 환경의 FGS 10초 윈도우 크래시 루프, 워처의
구 백엔드 잔존 버그, 에셋 내 죽은 서버 IP, 백엔드 하드 킬)도 함께 해결했다.

## 주요 변경

### 1. 앨범 → 갤러리 `Pictures/oojoo` (요구사항 1)

`GalleryPublisher`(slave, 신규)가 `PlantAlbum.add` — 성장 사진/즉시 촬영/
원동기 동기화 사진의 단일 초크포인트 — 에 후킹된다.

| | |
|---|---|
| **API 29+** | MediaStore `insert`(RELATIVE_PATH `Pictures/oojoo`) + IS_PENDING 플로우 — 권한 불필요, 즉시 인덱싱 |
| **API 24~28** | 공용 경로 파일 복사 + `MediaScannerConnection` 스캔 — `WRITE_EXTERNAL_STORAGE`(maxSdkVersion=28) 위임 시에만, 아니면 로그 후 스킵 |
| **표시 이름** | `p_<yyyyMMdd_HHmmss>_<plantId 6자>.jpg` — 단일 폴더라 같은 초 다중 식물 촬영의 충돌 방지 |
| **실패 처리** | 앱 내부 앨범 + 백엔드 업로드는 이미 완료된 상태이므로 발행 실패는 로그만 |

디바이스 실측 (API 34, `capture_photo` 명령 + 기동 직후 성장 캡처):

```
/storage/emulated/0/Pictures/oojoo/p_20261120_063502_-fIB9M.jpg   (59,988B)
content query content://media/external/images/media
  bucket_display_name=oojoo  relative_path=Pictures/oojoo/
  is_pending=0  owner_package_name=com.oojoo.farm.slave
  resolution=1856×1392  (EXIF orientation/f_number/iso 포함 — CameraX 실캡처)
```

동일 사진이 백엔드 `data/photos/`에도 업로드됨(동일 바이트) — 3개 경로
(내부 앨범/갤러리/백엔드)가 한 캡처에서 모두 생성되는 것을 확인.

### 2. 실시간 카메라 스트리밍 (요구사항 2)

LAN 직결 MJPEG — 백엔드 경유 없음, 신규 의존성 없음.

| 역할 | 구현 |
|---|---|
| **slave 스트림 서버** | `MjpegStreamer` — raw ServerSocket `:8613`, `multipart/x-mixed-replace`, 엔진 구동 중 상시 리스닝(클라이언트 없으면 프레임 생성 0). 최신 프레임을 ~5fps로 전송, 3초 staleness 가드 |
| **프레임 공급** | 기존 `ImageAnalysis` 분석 콜백이 매 프레임을 640w q70 JPEG로 `CameraHolder.latestFrame`에 발행(best-effort, 분석 플로우 무방해) |
| **URL 보고** | 하트비트 `streamUrl` = `http://<LAN IPv4>:8613/stream.mjpg` — `slaves.stream_url`(ensureColumn 마이그레이션)에 저장, http(s)만·200자 이하, 무효/미보고 시 기존값 유지 |
| **마스터 UI** | LiveCameraScreen "📡 실시간 보기" 모드 — slaves 목록에서 stream_url 조회 → WebView `<img>`로 multipart 렌더, 중지 버튼·미보고/오류 상태, i18n 8문자열(ko/en) |
| **3초 캡처** | 미변경 — 같은 화면에서 모드 추가 방식 |

호스트 측 실측 (`adb forward tcp:8613` 경유):

```
curl http://127.0.0.1:8613/stream.mjpg  (8초)
  → 64,933B, 11개 image/jpeg 파트, 480×640 JFIF JPEG (ICC 프로필 포함)
```

**환경 한계**: 에뮬레이터의 가상 카메라는 정적 장면이라 11개 프레임의
MD5가 동일했다 — 파이프라인(카메라→분석→발행→송신→클라이언트)은
전구간 검증됐고, 실카메라에서는 프레임이 바뀐다(코드상 프레임 콘텐츠
차이 없음 = 카메라의 문제 아님).

### 검증 한계 (주지)

- **마스터 라이브 뷰 렌더링** — 코드는 컴파일+로케일+API(stream_url 반환)
  검증 완료, WebView 렌더는 headless(터치 불가)에서 직접 확인 불가.
  클리어텍스트는 마스터 매니페스트 `usesCleartextTraffic=true` 가 허용.
- **MJPEG 프레임 변화** — 에뮬레이터 가상 카메라가 정적이라 동일 프레임
  반복. 파이프라인 전구간은 검증됨.
- **식물 동기화 주기** — `loadPlant()`는 엔진 기동 1회. 마스터가 나중에
  식물 등록하면 슬레이브 재기동까지 미반영 (기존 동작, 이번 범위 아님).

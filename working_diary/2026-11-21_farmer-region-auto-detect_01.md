## ① 지역 자동 추론 (`FarmerEngine.kt`)

**기존 상태:**

- farmer는 `LocationUtil.resolve()`(GPS→network→passive)로 좌표를 얻어 하트비트에 lat/lon 보고 — 이미 구현됨
- 백엔드 `GET /api/weather/coords`는 좌표를 **역지오딩(BigDataCloud→Open-Meteo 폴백)해 지역명**을 `region`으로 반환 — 이미 구현됨
- 그런데 farmer가 이 응답 region을 **저장하지 않고 버림** → 지역명은 마스터가 원격 정책으로 설정한 값(`syncPolicy`의 `p.region`)에만 의존
- 추가 문제: `syncPolicy`가 5분마다 원격 정책 지역으로 덮어써서, 자동 추론값이 있어도 유지되지 않음

**구현:**

- `fetchWeather()` — 좌표 기반 응답의 region(역지오딩 지역명)을 `Prefs.setRegion()`으로 자동 저장. 역지오딩 실패 시 백엔드가 반환하는 좌표 문자열 폼백(`"37.12, 127.10"` 형태)은 `COORD_REGION` 정규식으로 제외
- `syncPolicy()` — 기기 위치(`farmLoc`)가 있으면 자동 추론 지역이 우선, **원격 정책 지역은 위치가 없을 때만 fallback**으로 적용 (5분마다 덮어쓰는 것 방지)

**동작 흐름:**

```
엔진 시작/30분 루프:
  LocationUtil.resolve() → lat/lon (권한: 매니페스트 + MainActivity 런타임 요청 — 기존)
  → GET /api/weather/coords → 백엔드 역지오딩 → region(예: "용인시 처인구 동백동 부근")
  → Prefs.setRegion() 자동 저장 + 로그 "지역 자동 설정"
  → 이후 하트비트 region 보고도 자동 추론 지역 사용
```

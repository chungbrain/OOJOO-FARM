## 생성기 방식

- JS: `import ... from './x.js'` / `import('...')` 상대 경로만 (외부 패키지 제외). 백엔드는 `db.js` 로 가는 화살표와 `app.js` 의 라우터 마운트를 생략(그래프가 엉키지 않게 — 마운트는 API 지도에).
- Kotlin: 같은 패키지끼리는 import 가 없으므로, 주석·문자열을 지운 본문에서 다른 파일의 최상위 공개 선언(class/object/interface/fun, 4자 이상, 이름 중복 제외) 이름이 나오면 의존으로 본다. 대부분 파일이 쓰는 허브 파일(Master: Models/ApiClient 등)은 화살표 생략하고 ★ 표시.
- API 지도: `app.js` 마운트 + 라우트 파일의 `r.get/post/...` 경로와 앱 `ApiService` 의 `@GET/@POST...` 경로를 세그먼트 단위로 매칭(파라미터 양쪽 허용, 고정 세그먼트 많은 쪽 우선). 앱 엔드포인트 100개(Master 78 · Farmer 22, `/health` 포함) 모두 백엔드 라우트와 매칭됨.

## 검증

- Mermaid 렌더 검사: 두 문서의 다이어그램 23개를 mermaid 11.4.1 로 헤드리스 Edge 에서 렌더 → **23/23 오류 없음**. 시스템 구성·시퀀스·백엔드 그래프는 캡처해서 눈으로 확인
- 처음 생성한 백엔드 그래프가 엉켜 보여 원인 확인 — Windows 경로(`\`)라 `db.js` 화살표 숨김이 안 먹고 있었음 → 저장소 상대 '/' 경로로 비교하게 고침 (106 → 44 화살표)
- 쉘에서 `\\b` 가 백스페이스 문자로 들어가 정규식이 깨진 것을 발견해 고침 (`/health` 매칭 실패 원인)
- `node scripts/code-graph.mjs --check` 통과

## 추가: 영문 버전 (영문이 기본)

- 루트 README 와 같은 규칙으로 **영문이 기본**, 한국어는 `_kor` 파일.
  - `docs/code-graph/README.md` → 영문으로 새로 작성 (다이어그램 16개 모두 번역, 구조·파일·함수 이름은 그대로)
  - 기존 한국어 문서는 `docs/code-graph/README_kor.md` 로 이동 (링크를 `generated_kor.md` 로 바꿈)
  - `scripts/code-graph.mjs` 가 한 번 분석해서 `generated.md`(영문)와 `generated_kor.md`(한국어)를 함께 만든다. 문구는 스크립트 위쪽 `L.en` / `L.ko` 에 모음. Mermaid 노드 id 는 언어와 무관한 키(`backend`, `mm`, `master`, `farmer`)로 만든다
  - `--check` 는 두 파일을 모두 확인하고, Windows(core.autocrlf=true) 체크아웃의 CRLF 를 LF 로 맞춰 비교
- 각 문서 머리에 다른 언어 문서 링크. 루트 `README_kor.md` 의 코드 그래프 링크는 `docs/code-graph/README_kor.md` 로
- 검증: 네 문서의 다이어그램 46개(16+16+7+7)를 mermaid 11.4.1 / 헤드리스 Edge 로 렌더 → **46/46 오류 없음**, `node scripts/code-graph.mjs --check` 통과. 한국어 생성 결과는 머리말 링크와 노드 id 외에는 이전과 같음
